# 予想の事前登録 — 形態素分割（kagome・IPA・原形・機能語除去）に替えたら何が起きるか

🔴 **これは測定前に書かれた文書である。** `internal/lexical/kagome` の実装前に、設計担当（コーディネーター）が
予想を登録したものであり、kagome での `make eval` は1回も実行していない。

🔴 **この文書は測定後に書き換えない。** 実測との突き合わせは測定レポートで行い、ここは凍結する。

## 比較の起点（bigram・Postgres・rounds=5・2026-09-02）

| 構成 | `recall@10` | `MRR` |
| --- | ---: | ---: |
| 語彙のみ（bigram） | 0.620 | 0.736 |
| ハイブリッド alpha=0.8（bigram） | 0.724 | 0.807 |

## 測定される構成

分割規則は ADR 0018 Decision 2（NFKC・小文字化・ASCII 語は1語・kagome 通常モード・原形・記号／助詞／助動詞を除去）。
語彙スコアは `ts_rank`（正規化 0）・合成は加重和（クエリ内正規化）。bigram と**分割器以外は同一条件**。

## 総合値の予想

- **語彙のみの `recall@10` は動かない**（±0.02 の帯の中）。形態素は「何を拾うか」より「何を拾わないか」を変える
- **語彙のみの `MRR` は上がる**（+0.02〜+0.05）。語境界を跨いだ偶然一致（「の索」「を張」）が消え、
  上位の並びからノイズが減る
- **ハイブリッド alpha=0.8 は 0.724 ± 0.02**。総合値では Q-2 を決められない（bigram のときと同じ）
- **`alpha` のプラトーは動く可能性がある**（語彙スコアの分布が変わる）。0.8 がプラトーに残るかは五分

## タグ別の予想

| tag | bigram 語彙のみ | 予想 | 根拠 |
| --- | ---: | --- | --- |
| `exact-term` | 0.85 | **動かない** | 識別子は ASCII 語規則で bigram と同じトークンになる |
| `compound` | 0.93 | **下がる**（−0.05〜−0.15） | 複合名詞を形態素に切ると「索引作成」が「索引」「作成」に分かれ、クエリ側の複合語と部分一致になる。bigram は隣接情報を持っていた |
| `particle` | 0.48 | **動かない** | 助詞を捨てるので「が／を」の撃ち分けは原理的にできない。v2（助詞を残す）で試す設計 |
| `orthography` | 0.56 | 動かない | 正規化は同じ前処理で吸収済み。kagome の未知語処理が表記ゆれを助けるとは予想しない |
| `synonym` / `paraphrase` | 0.30 / 0.44 | **動かない** | 字面の不一致がタグの定義 |
| `numeric` | 0.61 | 動かない | 数字は ASCII 語規則で同じ |
| `negation` | 0.73 | 微増の可能性 | 「ない」を助動詞として捨てるので、否定の有無で語彙が変わらなくなる＝ベクトル側の判断が通りやすい。ただし語彙のみでは逆に区別できなくなる。**ハイブリッドでのみ微増**と予想 |

## latency の予想

- トークン数が減る（bigram は N 文字で N−1 トークン、形態素は語数）ので `tsvector` が小さくなり、
  **埋め込みを除く p95 は下がる**（14.4ms → 10ms 前後）。分割そのものの CPU 時間は取り込み側に乗り、検索側では1クエリぶんだけ

## この予想が外れたら意味を持つこと

- `compound` が下がらなければ、「bigram は隣接情報で複合語を守っている」という理解が誤り
- `MRR` が上がらなければ、bigram の偶然一致はそもそも上位を汚していない（`ts_rank` の中で埋もれている）
- 総合値が動いたら、bigram と形態素の差はこのコーパスでは「ノイズの量」ではなく「拾える語の集合」の差である
