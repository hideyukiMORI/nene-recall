# 評価 2026-09-02 — 語彙検索とハイブリッド合成（Q-1・Q-2・Q-3 の実測）

要件定義の **Q-1（tsvector か BM25 か）・Q-2（bigram か形態素か）・Q-3（`alpha` の最適値）** を
実測で決着させるための測定。**予想は測定前に別文書へ事前登録済み**
（[`2026-09-02-lexical-prediction.md`](2026-09-02-lexical-prediction.md)・コミット `d9eda6e`）。

⚠️ **本書は測定結果のみ。判断は ADR 0014（Q-1/Q-2）と ADR 0015（Q-3）で行う。**
判断は 2026-09-02 に着地した:
[ADR 0014 — 語彙検索は Go 側 bigram + `tsvector`、長さ正規化なし](../adr/0014-lexical-search-is-tsvector-over-bigram.md) /
[ADR 0015 — 合成は加重和（クエリ内正規化）・`alpha` 既定 0.8](../adr/0015-fusion-is-weighted-sum-with-alpha-0.8.md)。

## 1. 単体の比較 — 🔑 語彙検索がベクトル検索を上回った

| 構成 | `recall@10` | `MRR` |
| --- | ---: | ---: |
| ベクトルのみ（基準線） | 0.596 | 0.705 |
| **語彙のみ（bigram・`ts_rank` 正規化なし）** | **0.620** | **0.736** |
| 語彙のみ（`ts_rank` 長さ正規化 `2\|32`） | 0.544 | 0.496 |

⇒ **Q-1 の軸2（文書長の正規化）は決着**: `ts_rank` の長さ正規化は**有害**だった。既定を `0` に変更済み。

🔴 **第二注釈が警告した長文交絡は否定された。** 長文 gold（>520字）の recall はベクトル 0.267 /
正規化なし 0.200 / 長さ正規化 0.067。**正規化なしはベクトルより長文に弱い**ので、
その優位は長文優遇では説明できない。**この切り分けはハーネスの長さ別内訳が無ければできなかった。**

## 3. 🔴 加重和が機能していなかった（スケールが3桁違う）

| | 範囲 | 中央値 |
| --- | --- | ---: |
| `vector_score` | 0.23〜0.74 | 0.44 |
| `lexical_score`（生の `ts_rank`） | 0.000〜0.0036 | **0.00016** |

`0.3 × 0.0036 = 0.001` は `0.7 × 0.44 = 0.31` に敵わない。実測でも
**`alpha=0.7` と `alpha=1.0` で順位が違うクエリは 58 件中 1 件だけ**だった。

🔑 **原因は `ts_rank` のフラグ 32 が「有界化」であって「再スケール」ではないこと。**
`rank/(rank+1)` は rank が小さいとほぼ恒等写像になる。**有界であることと、
比較可能な尺度であることは違う。**

## 4. 融合方式の比較 — 加重和（クエリ内正規化）が RRF に勝った

| 方式 | `recall@10` | `MRR` |
| --- | ---: | ---: |
| **加重和 + `lexical` をクエリ内で [0,1] 正規化（alpha=0.8）** | **0.724** | **0.807** |
| RRF（順位融合・k=60） | 0.694 | 0.723 |

⇒ **要件定義 F-4 と OpenAPI の `alpha` 契約を変える必要はない。**

⚠️ **この RRF は古典的 RRF と条件が違う。** 索引が無く全行に順位を振るため、語彙が当たらない行が
`RANK()` で同順位に固まり、語彙1位のすぐ次に全部並ぶ。実測: k=60 で
`vector 1/61+1/62 = 0.03252` / `lexical1位 1/63+1/61 = 0.03227` — **語彙1位が買えたのは
1つ順位を上げることだけ**。⇒ **候補集合を絞る構成（項目7 の HNSW 導入後）では RRF の評価が変わりうる。**
テスト `TestRRFGivesLittleCreditWhenFewDocumentsMatch` がこの性質を固定している。

## 5. `alpha` スイープ（Q-3）

| `alpha` | `recall@10` | `MRR` |
| ---: | ---: | ---: |
| 0.0（語彙のみ） | 0.620 | 0.736 |
| 0.3 | 0.654 | 0.733 |
| 0.5 | 0.678 | 0.764 |
| 0.6 | 0.688 | 0.786 |
| 0.7 | 0.708 | 0.788 |
| **0.8** | **0.724** | **0.807** |
| 0.9 | 0.721 | 0.805 |
| 0.95 | 0.666 | 0.763 |
| 1.0（ベクトルのみ） | 0.596 | 0.705 |

**最大値から −0.02 以内のプラトーは 0.7〜0.9。** 設計規約どおり argmax を採らずプラトーで選ぶと、
**中心かつ最大値である `alpha = 0.8`** が候補になる。0.95 で急落するので端は選ばない。

⚠️ **`alpha` の最適値は正規化方式に条件付きである。** 「`lexical` をクエリ内で [0,1] に正規化した場合」の
値であり、正規化を変えたら測り直しになる。

⚠️ **この 259 チャンク・ADR 語彙の濃いコーパスでの値であり、一般の日本語文書に外挿しないこと**
（`testdata/eval/README.md` の限界節）。

## 6. 到達点

| | `recall@10` | `MRR` |
| --- | ---: | ---: |
| 基準線（ベクトルのみ） | 0.596 | 0.705 |
| **ハイブリッド（alpha=0.8）** | **0.724** | **0.807** |
| 差 | **+0.128** | **+0.102** |

⚠️ 58クエリなので1クエリの成否で総合 recall が 0.017 動く。+0.128 はその**7倍以上**であり、
ゆらぎでは説明できない。ただし**タグ別は n=6〜8 なので、タグ単位の差は1クエリで 0.14 動く**。

## 7. 残る課題

- **最大の穴 `paraphrase` 0.44 は語彙検索では埋まらなかった**（予想どおり ±0.00）。
  ⇒ **Q-4（reranker）を「Phase 1 は入れない」と決めた判断は、この数字を見る前のものである**
- Q-2（bigram か形態素か）は **bigram 側しか測っていない。** 形態素解析器は ARC-004 により
  ADR が要るため、C1/C2 の結果を見てから判断する設計にした。⇒ **未決着**
- latency はこの測定では正本にしない（rounds=1）。決定した構成で rounds=5 の正本を取り直すこと
  → **取り直した**（[`2026-09-02-eval-hybrid-latency.md`](2026-09-02-eval-hybrid-latency.md)）。
  既定構成の p95 は 埋め込み込み 74.6ms / 除く 14.4ms。品質指標は rounds=1 と完全に一致した。
  🔑 その測定で分かったこと: **`alpha` では語彙検索の追加コストを測れない**（`alpha=1.0` でも
  `ts_rank` は全行に計算される）。統制測定で追加コストは p95 +11.6ms と判明した
