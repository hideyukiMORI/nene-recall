# `tools/wikidistract` — 10万件の「無関係文書」を作る

日本語 Wikipedia のダンプから 100〜500 字の段落を決定的に選び、評価ハーネスへ
投入できる JSONL を書く。設計の根拠は
[ADR 0019](../../docs/adr/0019-large-scale-benchmark-corpus.md)。

🔴 **これは開発者の道具であって成果物ではない。** `make build` の対象に入れない
（`cmd/eval` と同じ線引き）。生成した JSONL もダンプもキャッシュも
**リポジトリにコミットしない**。再現性は「取得手順 ＋ チェックサム」で担保する。

---

## 置き場所

すべて **`bin/wikidistract/`** に置く。`bin/` は `.gitignore` 済みである。

| 何 | 場所 | 大きさ |
| --- | --- | --- |
| ダンプ | `bin/wikidistract/jawiki-<日付>-pages-articles1.xml-p1p114794.bz2` | 385 MB |
| 生成した紛れ込み | `bin/wikidistract/distractors-100k.jsonl` | 62 MiB |
| 埋め込みキャッシュ | `bin/embed-cache/`（`make eval EVAL_EMBED_CACHE=...`） | 数百 MB |

⚠️ **`make clean` は `bin/` を丸ごと消す。** ダンプを取り直したくなければ、
`-in` に別の場所を指してもよい（ツールは置き場所を知らない）。

## 手順

```bash
mkdir -p bin/wikidistract

# 1) ダンプを取る（385 MB・進捗が出る）
curl -L -o bin/wikidistract/jawiki-20260901-pages-articles1.xml-p1p114794.bz2 \
  https://dumps.wikimedia.org/jawiki/20260901/jawiki-20260901-pages-articles1.xml-p1p114794.bz2

# 2) 10万件を選ぶ（実測 36 秒）
go run ./tools/wikidistract \
  -in  bin/wikidistract/jawiki-20260901-pages-articles1.xml-p1p114794.bz2 \
  -out bin/wikidistract/distractors-100k.jsonl \
  -count 100000

# 3) 評価に足す（ADR 0019）
make eval EVAL_LABEL=100k \
  EVAL_DISTRACTORS=bin/wikidistract/distractors-100k.jsonl \
  EVAL_EMBED_CACHE=bin/embed-cache
```

### 実測の記録（2026-09-02）

| 項目 | 値 |
| --- | --- |
| ダンプ | `jawiki-20260901-pages-articles1.xml-p1p114794.bz2`（403,287,064 バイト） |
| ダンプの sha256 | `0f2bbf3131e2e6ce7d2c5677687bab04d79d78b08cd2f5f01b46f9b2956b455d` |
| 出力 | `distractors-100k.jsonl`（64,971,085 バイト・100,000 行） |
| 出力の sha256 | `514739b7f396b204182a1b166808be596849432758c0ed2d2107197b85a53556` |
| 生成時間 | 35.6 秒 |
| 走査したページ | 11,669（名前空間 0）・最後に採用したページ ID 15,637 |

🔑 **11,669 ページで 10万件に達した。** ダンプは p1〜p114794 を含むので、
1割を読んだところで止まっている。**`latest` ではなく日付付きの URL を使うこと。**
`latest` は中身が入れ替わるので、同じ URL から同じ sha256 が出なくなる。

### 🔴 追記（2026-09-03）— 上の sha256 は再現しない。日付付き URL でも足りない

2026-09-03 に**同じ URL** から取り直したところ、**別のファイル**が来た。

| 項目 | 2026-09-02 に記録した値 | 2026-09-03 に取り直した値 |
| --- | --- | --- |
| ダンプの大きさ | 403,287,064 バイト | **403,417,796 バイト** |
| ダンプの sha256 | `0f2bbf31…6b455d` | **`6d0fc727…f862318`** |
| 出力の大きさ | 64,971,085 バイト | **64,973,924 バイト** |
| 出力の sha256 | `514739b7…5a53556` | **`2b44ccee…56fdbd2a0`** |
| 走査したページ / 最後のページ ID | 11,669 / 15,637 | **11,669 / 15,637（同じ）** |

🔑 **分割器は決定的なままである。** 走査ページ数も最後のページ ID も一致し、出力は
どちらも 100,000 行ちょうどである。⇒ **変わったのは入力のほうである。**

原因は取得の時刻だった。`dumpstatus.json` は `articlesdump` ジョブの完了を
**2026-09-02 13:49:02 UTC（＝22:49 JST）**と記録しており、そこに載っているファイルの
大きさは 403,417,796 バイト——**2026-09-03 に取り直した側**と一致する。
⇒ 09-02 の取得は**ジョブが終わる前**に走り、生成途中のファイルを掴んだ。

⚠️ **途中のファイルは完成版の先頭部分ですらない。** 完成版の先頭 403,287,064 バイトの
sha256 は `d3d9adcb…` で、記録された `0f2bbf31…` とは一致しない（2026-09-03 実測）。
⇒ 「途中まで同じで、続きが足されただけ」ではないので、**取り直しても 09-02 の
コーパスは復元できない。**

🔴 **手順に1つ足すこと**——ダウンロードの前に完了を確かめる:

```bash
curl -s https://dumps.wikimedia.org/jawiki/20260901/dumpstatus.json \
  | python3 -c "import json,sys; j=json.load(sys.stdin)['jobs']['articlesdump']; print(j['status'], j['updated'])"
# done 2026-09-02 13:49:02  ← done でなければ取らない
```

🔑 **`latest` を避けるだけでは足りない。** 日付付きの URL は「その日付の内容」を指すが、
**その内容が確定するのは日付の翌日以降**である。ジョブが `done` になる前に取ると、
同じ URL から同じ sha256 は二度と出ない。

⇒ **帰結**: [before](../../docs/benchmarks/2026-09-02-eval-100k-before-index.md) と
[after](../../docs/benchmarks/2026-09-02-eval-100k-after-index.md) が使った10万件と、
2026-09-03 以降に生成する10万件は**別のコーパス**である。件数・分布・生成規則は同じだが、
本文は同一ではない。以後の 10万件の測定は、この差を条件として明記してから並べること。

## なぜ `pages-articles` の第1パートなのか

ADR 0019 は形式の選択を実装レーンに委ねている。実在を確認したうえで
**`pages-articles1`（wikitext・第1パート）**を選んだ。

| 候補 | 実在 | 採否 |
| --- | --- | --- |
| `jawiki-<日付>-pages-articles1.xml-p1p114794.bz2` | ✅ 385 MB | **採用** |
| `other/cirrussearch/`（旧・CirrusSearch content dump） | ⚠️ 12.2 GB・**廃止済み** | 却下 |
| `other/cirrus_search_index/`（新・CirrusSearch） | ✅ 643 MB × 14 分割 | 却下 |

### CirrusSearch を採らなかった理由

CirrusSearch の `text` は**プレーンテキストで、wikitext の除去が要らない**。
それでも採らなかったのは、決定性の条件が合わないためである。

1. **旧 `other/cirrussearch/` は公式に廃止されている。**
   `DEPRECATED.txt` が「更新を止めた・新しい場所へ移った」と明記しており、
   最新のダンプは 2025-12-29 で止まっている。廃止された経路を再現手順に書けない
2. 🔴 **新 `other/cirrus_search_index/` は ページ ID 順に並んでいない。**
   先頭を取って復号すると `page_id: 331827` から始まる（実測）。
   ADR 0019 の選択規則は「ページ ID 昇順・先頭から」なので、この形式では
   **1シャード（643 MB・展開後 数 GB）を全部読んでから並べ替える**ことになる。
   「10万件に達したら止める」が効かず、必要な最小のデータで済まなくなる
3. 分割の仕方（どの記事がどのシャードに入るか）はダンプの都合で決まる。
   「14分の1を読んだ」という条件は、こちらの規則では説明できない

`pages-articles` は逆で、**物理的にページ ID の昇順**である。1回のストリーム
走査で先頭から選び、10万件で止められる。並べ替えも全読みも要らない。

### 代償と、その受け止め方

wikitext の除去が要る。忠実なパーサは書かず、**粗い除去**（`wikitext.go`）と
**除外規則**（`paragraph.go`）の二段で受け止めている。

- 粗い除去: コメント・`<ref>`・表 `{|...|}`・テンプレート `{{...}}`（入れ子対応）・
  `[[...]]`（画像と分類は本文ごと捨て、`[[A|B]]` は `B` を残す）・外部リンク・
  魔法語・残った HTML タグ・`'''` 等の強調・実体参照
- 除外規則: 記法の断片（`[[`・`{{`・`<`）が1つでも残っている段落は**捨てる**

⇒ 除去がしくじった段落は投入されず、通った段落は素の日本語になる。
**パーサの完全性を、選別の厳しさで置き換えている。**

## 選択規則（決定的）

| 規則 | 実体 |
| --- | --- |
| ページ ID 昇順 | ダンプの並び順をそのまま使う（並べ替えない） |
| 名前空間 0 のみ | `<ns>` を見る。リダイレクトは本文が `#REDIRECT [[...]]` の1行なので、行頭 `#` の規則が落とす |
| 各ページの段落を先頭から | 1行を1段落として扱う |
| 100〜500 字 | **ルーン数**で数える（バイト数ではない） |
| 空行・見出し・箇条書き・表を除く | 行頭が `=` `*` `#` `:` `;` `\|` `!` `{` `}` 空白 `-` なら捨てる |
| 記法の残りを含む段落を捨てる | `[[`・`{{`・`<` のいずれかを含めば捨てる |
| 10万件に達したら止める | `-count` |

出力の1行は `internal/eval` の `Distractor` そのものである。

```json
{"document_id":9000005,"source_id":9000000,"chunk_index":0,"content":"アンパサンド（&, ）は…"}
```

- `document_id` = ページ ID + 9,000,000
- `source_id` = 9,000,000（全件が同じ取り込み元に属する）
- `chunk_index` = そのページの中での通番（0 始まり）
- 🔴 **`eval_key` を持たない。** 紛れ込みは**どのクエリの正解にもならない**ので、
  人が付ける安定キーが要らない。書いた行は読み込み時にエラーになる
  （`decodeLine` が未知のフィールドを拒否する）。レポートに出る表示名
  `distractor:9000005#0` は `document_id` と `chunk_index` から機械的に作られる

🔑 **型をツールと評価ハーネスで共有している**（`tools/wikidistract` が
`internal/eval.Distractor` を import する）。生成物がリポジトリに入らない以上、
様式のずれを捕まえる手立てはコンパイルしかない。

## ライセンスと帰属

本文は **日本語版ウィキペディア**（<https://ja.wikipedia.org/>）に由来し、
**CC BY-SA 4.0** で提供されている。生成した JSONL を配布する場合は同じ条件が要る。
